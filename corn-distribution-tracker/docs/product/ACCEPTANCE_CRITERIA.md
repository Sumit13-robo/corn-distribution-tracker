# Acceptance Criteria / Release Gates

## Authentication and authorization
- [ ] Unauthenticated API requests to protected routes return 401.
- [ ] Distributor attempting to access another distributor's site, assignment, submission, photo or inventory account receives 403/404 without leaking protected details.
- [ ] Admin-only operations are rejected for distributor role at the server.
- [ ] Failed login throttling, invitation expiry, logout/refresh behavior, password reset, secure cookie/token settings, and admin bootstrap are tested/documented.

## Ledger correctness
- [ ] Every posted movement has positive quantity, valid source/destination semantics, actor, time, type and reference.
- [ ] Canonical quantity is Decimal/Numeric kg; rounding/unit conversion tests cover kg, quintals, tonnes and configured bags.
- [ ] Sum of balances by account reconciles to received stock net of documented sources/sinks such as approved loss adjustments.
- [ ] Concurrent submissions cannot reserve more than available stock.
- [ ] Approving one pending delivery twice creates exactly one stock movement.
- [ ] Rejected records do not change stock and release reservations.
- [ ] Posted movements and approved records are not destructively edited; correction uses reversal/compensating transaction plus audit.

## Geotagged evidence
- [ ] GPS coordinate ranges and required metadata are validated server-side.
- [ ] Reported accuracy, server time, user, site, distance, content hash and validation flags are stored.
- [ ] Low accuracy, off-site location, stale location, duplicate hash and metadata mismatch are flagged according to policy.
- [ ] Missing browser location/camera support gives actionable UI guidance and follows configured fallback policy.
- [ ] Private images are not publicly readable; authorized signed URLs expire and cannot be generated by a distributor for another user's evidence.
- [ ] UI says GPS/photo metadata are signals and not guarantees of authenticity.

## Operations and UX
- [ ] Admin dashboard, map, inventory, sites, distributor management, evidence review and analytics use real persisted API data.
- [ ] Distributor dashboard, assigned sites, site details and submission flow use real API data.
- [ ] All major lists are paginated; map filters match site list filters; filters/exports honor server-side authorization.
- [ ] Every major screen has loading, empty, error, retry and permission-denied states.
- [ ] Layout works at 360 px mobile width and desktop; keyboard navigation, visible focus, labels and status text are checked.
- [ ] Offline drafts survive reload where supported and clearly distinguish local-only from server-confirmed status.
- [ ] Structured logs redact secrets and sensitive evidence; readiness/liveness checks expose no internal secrets.
- [ ] Fresh checkout steps, migrations, tests, backup and restore guidance, HTTPS/CORS settings and environment variable descriptions are documented.

## Required final report
The builder must report actual commands run and pass/fail status for backend tests, frontend tests, lint, types, migrations and production builds; list any unimplemented requirements; explain how to provision the first admin and private object storage; and state any remaining launch blockers.
