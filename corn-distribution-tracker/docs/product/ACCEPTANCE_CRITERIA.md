## Authentication and authorization
- [ ] Unauthenticated API requests to protected routes return 401.
- [ ] Distributor attempting to access another distributor's site, assignment, submission, photo or inventory account receives 403/404 without leaking protected details.
- [ ] Admin-only operations are rejected for distributor role at the server.
- [ ] Failed login throttling, invitation expiry, logout/session-restore behavior, password reset, secure cookie settings, and admin bootstrap are tested/documented.

## Ledger correctness
- [ ] Every posted movement has positive quantity, valid source/destination semantics, actor, time, type and reference.
- [ ] Canonical quantity is Decimal/Numeric kg; rounding/unit conversion tests cover kg, quintals, tonnes and configured bags.
- [ ] Sum of balances by account reconciles to received stock net of documented sources/sinks such as approved loss adjustments.
- [ ] Concurrent submissions cannot reserve more than available stock.
- [ ] Approving one pending delivery twice creates exactly one stock movement.
- [ ] Rejected records do not change stock and release reservations.
- [ ] Posted movements and approved records are not destructively edited; correction uses reversal/compensating transaction plus audit.
- [ ] Idempotency is scoped by operation and payload-bound: identical retries replay, different payloads conflict, and legacy fingerprint-less keys fail closed.
- [ ] `LOSS`/`RETURN` adjustments and reversals cannot consume stock reserved by pending deliveries or overdraw the receiving account.
- [ ] Concurrent approvals serialize on the assignment row, and the current record's reservation is excluded from its own availability check.

## Geotagged evidence
- [ ] GPS coordinate ranges and required metadata are validated server-side.
- [ ] Reported accuracy, server time, user, site, optional distance when both a site reference and fix exist, content hash and non-location validation flags are stored. Name-only sites store a null distance.
- [ ] Duplicate hash, capture-time mismatch and unexpected file type are flagged according to policy. Low accuracy, off-site/stale location and EXIF GPS differences are not location warnings and never block approval.
- [ ] A submission can be manually approved from any recorded place; missing browser location/camera support gives actionable UI guidance without blocking submission.
- [ ] Private images are not publicly readable; authorized signed URLs expire and cannot be generated by a distributor for another user's evidence.
- [ ] Direct-to-S3 completion verifies size, decode, type and SHA-256; attachment re-verifies; private reads are bounded and re-check the hash, so same-size and oversized replacements are rejected.
- [ ] UI says GPS/photo metadata are signals and not guarantees of authenticity, and does not present location as an approval gate.

## Operations and UX
- [ ] Admin dashboard, map, inventory, sites, distributor management, evidence review and analytics use real persisted API data.
- [ ] Distributor dashboard, assigned sites, site details and submission flow use real API data.
- [ ] All major lists have a documented bounded-loading/pagination policy; delivery-map filters match the list contract, and filters/exports honor server-side authorization.
- [ ] Every major screen has loading, empty, error, retry and permission-denied states.
- [ ] Layout works at 360 px mobile width and desktop; keyboard navigation, visible focus, labels and status text are checked.
- [ ] Offline drafts survive reload where supported and clearly distinguish local-only from server-confirmed status.
- [ ] Structured logs redact secrets and sensitive evidence; readiness/liveness checks expose no internal secrets and readiness probes configured storage.
- [ ] Fresh checkout steps, migrations, tests, backup and restore guidance, HTTPS/CORS settings and environment variable descriptions are documented.
- [ ] CI covers backend lint/type/migration/tests, web lint/type/unit/build, dependency audit and Playwright E2E; `TRUST_X_FORWARDED_FOR` remains opt-in behind a proxy that overwrites the header.
- [ ] CSP/COOP/frame/referrer headers and HSTS/redirect policy are verified at the actual ingress; the process-local rate-limit store is bounded and a shared limiter is used before horizontal scale-out.

## Required final report
The builder must report actual commands run and pass/fail status for backend tests, frontend tests, lint, types, migrations and production builds; list any unimplemented requirements; explain how to provision the first admin and private object storage; and state any remaining launch blockers.
